# v1.7.1

Upgrade if you run 1.7.0 or earlier and open projects you did not write, connect to servers you care about, or let an agent use the skill, knowledge-base or benchmark commands. 1.7.1 closes the gaps that 1.7.0 left open in its own fixes: a project file could still move an `operate` fleet into workbench mode, a keychain password could still be claimed by name alone, two accounts on one host could share a web session, and several tools and commands still skipped the gates. It also fixes three tools that had silently failed over HTTP since 0.9.9.

Security advisory: [GHSA-3wfx-w6qw-hqf4](https://github.com/intersystems-community/iris-agentic-dev/security/advisories/GHSA-3wfx-w6qw-hqf4). It covers 1.7.0 and 1.7.1 together. If you run 1.6.4 or earlier, read the [1.7.0 notes](v1.7.0.md) too.

Run `check_config` first if a call that worked on 1.7.0 is refused now. It lists what iad set aside and why.

## Breaking changes

### Configuration files and trust

- **A project file's `mode` is a loosening setting.** A file whose `mode` is anything but `operate` is set aside as `workspace:mode` until you trust it, so a cloned repository can no longer turn an `operate` fleet into a workbench and drop the role gate. `mode = "operate"` still applies without trust, and `trust --show` lists `mode`.
- **Moving the operator file off `operate` waits for a restart.** Changing `mode` to another value mid-session, removing the key or deleting the file is held as `operator:mode`. A change to `operate` applies at once.
- **The config-file search stops at the repository root.** It never climbs above your home directory and never reads `/`.
- **Some directories are never the project directory:** `/`, `/Users`, `/home`, `/tmp`, `/private/tmp`, `/var/tmp`, `/Users/Shared`, `/Users/Public`, `C:\Users\Public`, `/Volumes`, `/mnt`, `/media`, one level below those mount roots, and any directory that holds your home. This holds for the working directory, `--workspace` and `OBJECTSCRIPT_WORKSPACE`. `iris_compile`, `kb index` and `iris_symbols_local` refuse paths there with `no_workspace`. A project one level or more below a mount root, such as `/Volumes/work/proj`, still works.
- **`server: ""` is `INVALID_PARAMS`** for every tool that names a server, including `server_a` and `server_b` on the compare tools and when resuming an elicitation. Leave the argument out to use the default.
- **No response text tells the agent to edit a project file.** `check_config`, `iris_test_server` and the NoPWS hint now point at `iris_select_container`, `iris_add_server`, the operator file or an environment variable.

### Credentials, sessions and transport

- **A 1.6.x keychain password is never claimed.** iad used to read a Server Manager keychain item for a `servers.json` entry that matched no profile, then send it to that entry's host. It is now never read into a connection, never sent and never copied. The name appears in `check_config` under `set_aside` as `<name>:legacy_keychain`. Run `iris_add_server` for that name with its password and iad saves it for the address you give. Insiders, VSCodium and VS Code profile users do this once.
- **Two accounts on one host hold separate web sessions.** Each endpoint-and-account pair has its own cookie store, logged out on exit as before. Credential probes such as `iris_test_server` use a private session, so a wrong password can no longer pass because another session was already open.
- **iad no longer follows redirects from an IRIS server, or from the LLM provider.** A 3xx comes back as the answer. If you relied on an http-to-https or trailing-slash redirect, put the final address in the connection. `iris_doc_search` still follows up to three redirects on the docs site.
- **Bodies over 8 MiB from LLM, GitHub or docs hosts fail** with an error that names the cap. This covers `iris_generate`, `skill install`, skill fetches, manifest resolution and `iris_doc_search`. The skills, skill install and manifest clients also time out: 30 seconds to connect and 120 in total.
- **Each server's certificate setting is honoured on every path.** With `IRIS_TLS_VERIFY=false` at launch, a pool member that verifies certificates used to be reached without verification by `iris_test_server name=`, the compare tools, mirror `add_async` and `failover`, `global_preview`, `iris_global`, the namespace, database, mirror and performance tools, `query_audit_log`, `stream_inspect`, `my_access`, `capability_matrix`, the HL7 schema tools, the Mermaid tools, `resolve_storage` and `iris_execute`. They now use the addressed server's own client. If a client cannot be built, the call fails; it no longer falls back to the startup client.
- **In HTTP transport mode, state belongs to the session that made it:** confirmation tokens, terminal sessions, the source-control checkout cache and the metadata cache. The dictionary tools' cache keys also name the endpoint, the account and the `limit`. Connection state stays shared by design, so one session's `iris_select_container` moves the other sessions' default.

### Gates and SQL

- **`iris_query mode="write"` refuses a write it cannot count.** While `max_rows_affected` is in force (default 1000), an `UPDATE`, `DELETE` or `TRUNCATE` iad cannot count is refused with the new code `ROWS_NOT_COUNTABLE`: a join, a list of tables, `UPDATE t (cols) VALUES (…)`, `TRUNCATE TABLE %NOCHECK t`, or a modifier it does not know. `TRUNCATE TABLE` is counted and capped. `DELETE table` without `FROM`, and `%NOJOURN`, are counted. `%NOUNIQCHECK` and `%STARTTABLE` are not modifiers on IRIS 2026.2, which reads each as a table name, so they are refused. The `rows_check_skipped` response field is gone. A statement that starts with `;`, `(` or a quote is `DDL_NOT_ALLOWED`. One call changes at most 10,000 rows; `force` does not raise that ceiling.
- **A tool with no category is gated as `execute` and `admin`.** It is blocked under the `live` and `test` templates, and by any `allow` list that does not name both. `check_config` lists the deliberate exceptions in the new field `ungated_tools` (today only `check_config`).
- **The connection tools meet `allow` and the template.** `iris_select_container`, `iris_start_sandbox`, `iris_containers`, `iris_add_server`, `iris_remove_server`, `iris_import_servers` and `iris_reload_pool` are refused by an `allow` list without `admin`, and when the default server's template is `live` or `test`.
- **The skill and knowledge-base tools meet the default server's gates.** `skill`, `skill_community`, `kb`, `kb_index` and `agent_info` run code on the default server, so the template, `allow` and the write gate judge them, and strict read-only refuses them. `skill_forget` is destructive. `skill_list`, `skill_describe` and `skill_search` stay open, strict read-only included: when a gate refuses their server-side half, or read-only mode is strict, they answer from the bundled skills and say the server-side skills were not consulted.
- **`skill`, `kb`, `kb_index`, `skill_forget`, `skill_community` and `agent_info` are refused when the configuration file does not parse,** with `CONFIG_INVALID`, like every other tool that talks to IRIS. `skill_list`, `skill_describe` and `skill_search` answer from the bundled skills.
- **Strict read-only judges each call, not only each tool.** `iris_doc mode=compiled` reads the `.INT` routine through a class iad compiles on the server, so under `read_only = "strict"` it is refused with `READ_ONLY_STRICT`; the other `iris_doc` modes still work. A call strict does not know compiles is refused by the class runner before anything is sent, with `READ_ONLY_STRICT (scratch-class runner)` in the error.
- **Strict read-only and `irisAudit = true` cannot be combined.** Writing each audit record compiles a class on the server. The MCP server already refused to start with both; the `tool` command now refuses every tool that talks to IRIS with `READ_ONLY_STRICT_WITH_AUDIT`, naming both settings and where each is set, and `check_config` reports it. Remove one of the two.
- **`benchmark` and `capability-matrix` go through the same gates as every other call.** Both exit 1 with `READ_ONLY_STRICT` before connecting under strict read-only, and the template and `allow` apply to them. `capability-matrix` also exits 1 when its probe fails.
- **Reading message bodies needs `acknowledgePhi=true` under `dataPolicy = "allow"`:** `iris_interop_query` with `body_class`, `body_where`, `body_select` or `search_table`, `iris_message_body`, and `stream_inspect`. Without it the call is refused with `PHI_ACK_REQUIRED` before IRIS is contacted. `acknowledge_phi` works too. `stream_inspect` gains the argument. `block` and `redact` are unchanged. Update any prompt or skill that reads bodies on an `allow` server.
- **The SQL code-edit gate reads comments the way IRIS does.** It catches `%Dictionary` and `%Library.Routine` spellings broken up by comments, such as `%Dictionary/**/.ClassDefinition`, and checks a `CREATE` or `ALTER` body with its raw text as well as the lexed text. A comment that only mentions them no longer blocks the statement.
- **`iris_query` explain mode reads the statement with the shared SQL lexer.** It accepts a comment before `SELECT`, and refuses a second statement, a write keyword or `SELECT INTO` with `SQL_WRITE_BLOCKED` before sending anything. The role gate no longer asks for `confirm` on `/* c */ SELECT 1`.
- **A failure while building a refusal refuses the call.** It used to let the call through.
- **The release binary no longer ships test hooks.** The mock model answer and the refusal-failure hook are built only with the `testing` feature, which the release dependency no longer enables.

### VS Code extension 0.5.1

- **`iris-agentic-dev.scheme` and `iris-agentic-dev.tlsVerify` are user-level settings only.** A value in a workspace's `.vscode/settings.json` is ignored, so a cloned repository can no longer switch your connection to plain http or turn off certificate checking. If you set either in a workspace file, move it to your user settings.
- **A workspace `objectscript.conn` no longer inherits your saved password** unless the host, port, server name and username all match your user-level connection. If a project changes only the username, you are asked for the password instead.
- **The stable copy of the binary is hashed against the pin on every launch,** not only after a download.

## Fixes

- **`skill action=list`, `skill action=search` and `kb recall` work over HTTP again.** They had failed with `IRIS_EXECUTE_ERROR` since 0.9.9, because the ObjectScript they sent used escaped quotes that do not compile. A second bug behind it ran the recall loop one key too far.
- **`iris_debug source_map` and `map_int` work over HTTP.** `source_map` returns the `.INT` lines of each method a class declares, as objects instead of single numbers. `map_int` returns the class, method and line for an error place such as `<DIVIDE>Alpha+2^Pkg.Cls.1`; it used to answer "1" for every input. `source_location` is now `Method+line^Class`. `debug_map_int_to_cls` gets the same fix.

## For people who work on iad

New guard tests list everything of one kind and fail when something is not declared: every tool has a gate class, no tool that claims to be local opens a connection, every command-line subcommand is classified, no HTTP client is built outside the one builder, every configuration key is marked loosening or not, and every field of the HTTP session state is marked per-session or shared with a reason. A live sweep calls every read-only tool and fails on a compile or execution error. `docs/invariants.md` says what to declare when you add a tool, command, key, client or session field.

## Known limits

- The role gate's `confirm: true` comes from the agent. It stops an agent from writing to a server by mistake; it does not stop an agent that means to go ahead. To make a person approve writes, keep `write_tools_enabled` off for that server and turn it on when you want the write.
- `iris_query` in read mode can still read the Search Table, message-body and `Ens_Util.Log` tables directly. The data policy limits the interop tools, and only IRIS privileges limit SQL. Give the account iad uses no more than it needs.
- A read-only `SELECT` can still call a SQL function with side effects.
- Passwords are held in ordinary process memory and are not zeroed. A later release changes that.
