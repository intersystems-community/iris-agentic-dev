# v1.6.4

Upgrade if you run iad against IRIS on Windows, run code that moves the current device, or run
Claude Code on the binary the VS Code extension downloaded.
`iris_execute` and every tool built on it could answer `ERROR($DEVICE)` and call the output lost
when it was not.

## Notable fixes

- **The output capture check compares the device IRIS named.** iad sends output to a temp file
  and afterwards checks that the current device is still that file. It compared `$IO` with the
  string `TempFilename` returned, but `$IO` reports IRIS's own name for the file: lower-cased on
  native Windows, and rewritten for a path such as `/tmp/./x`. 1.6.0 compared the two without
  case, which covered only the first difference (#139). The check now records `$IO` right after
  selecting the capture file and compares against that.
- **Code that leaves the device at `$PRINCIPAL` keeps its output.** `Use 0`, `Use $PRINCIPAL`, or
  closing the device the code was writing to all leave the current device at the process's
  principal device. iad answered `ERROR($DEVICE)` and said the output was lost. It was not lost:
  what the code wrote before the move is in the capture file, and Atelier returns what it wrote
  after the move in its answer. iad now returns both, in order. A move to any other device, such as
  a file the code opened and left selected, is still an error.
- **Claude Code now follows the binary the VS Code extension downloads.** The extension kept each
  download in a version-named directory under its storage, `iris-agentic-dev-<version>/`, and
  [connecting.md](../connecting.md) told you to register that path with other MCP clients. The
  extension went on downloading new releases, but Claude Code, Cursor and the rest kept launching
  the version they were first given: one Windows user had 1.5.0, 1.6.0 and 1.6.3 on disk and
  Claude Code on 1.5.0. The extension now also keeps a copy at a fixed path,
  `<storage>/bin/iris-agentic-dev` (`.exe` on Windows), and replaces it on every update. On
  Windows, where a running `.exe` cannot be overwritten, the running copy is renamed aside and
  deleted once it exits. The next time VS Code starts the extension, it rewrites any entry in
  `~/.claude.json`, a workspace `.mcp.json`, Claude Desktop, Cursor, Windsurf or VS Code's
  `mcp.json` whose command names one of its own version directories, shows which files it changed,
  and asks you to restart those clients. Entries pointing anywhere else, including another editor's
  storage, are left alone, as are files with comments in them.

## Breaking changes

None.
