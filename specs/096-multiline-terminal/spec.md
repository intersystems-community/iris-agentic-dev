# Feature Specification: Multiline ObjectScript Auto-Route via .mac

**Feature Branch**: `096-multiline-terminal`
**Created**: 2026-09-02
**Status**: Draft

## Overview

`iris_execute` terminal mode processes input line by line. Multi-line ObjectScript with
`{}` blocks (if/else, for, try/catch) fails with a raw `<SYNTAX>` error. Agents trained
on modern ObjectScript naturally emit block syntax and hit this limit immediately on any
non-trivial script.

The fix is transparent auto-routing: when submitted code contains `{` or a newline,
`iris_execute` silently routes to a compile-and-run path — write the code as a `.mac`
routine with a unique name, compile via Atelier REST, execute via `Do ^IADTmpXxx`, delete
the routine after execution. The caller sees output as normal plus a
`transport: "mac_compile_run"` field indicating the path taken. Terminal mode stays
single-line only. No API change is required; the behavior is entirely internal.

---

## User Scenarios & Testing

### User Story 1 — Agent submits block-syntax ObjectScript (Priority: P1)

An agent running a diagnostic script writes an `If`/`ElseIf` block using `{}` syntax
and calls `iris_execute`. Today it gets `<SYNTAX>` with no explanation. After this fix,
the code runs transparently and the output is returned normally.

**Acceptance Scenarios**:

1. Given code `If (x=1) { Write "yes",! } Else { Write "no",! }`, When `iris_execute`
   is called, Then the response has `success: true`, non-empty `output`, and
   `transport: "mac_compile_run"`.
2. Given single-line code `Write $ZVERSION,!`, When `iris_execute` is called, Then the
   response has `transport: "terminal"` (or no transport field) — the fast path is
   unchanged.
3. Given code that is multiple lines but contains no `{`, When `iris_execute` is called,
   Then it routes through `.mac` compile-and-run (newline is sufficient trigger).
4. Given code that compiles but throws a runtime error, When `iris_execute` is called
   via the mac path, Then the response surfaces the IRIS runtime error as-is.
5. Given code that fails to compile, When `iris_execute` is called via the mac path,
   Then the response returns `success: false` with compilation errors — the temp routine
   is still deleted.

### User Story 2 — Cleanup on failure (Priority: P1)

The temp routine must not persist in the namespace after a failed execution. A lingering
`IADTmpXxx.mac` in a production namespace is unacceptable.

**Acceptance Scenarios**:

1. Given code that compiles but raises a runtime error, When `iris_execute` completes,
   Then `IADTmpXxx.mac` no longer exists in the namespace.
2. Given code that fails to compile, When `iris_execute` completes, Then the
   partially-written `.mac` file is deleted.
3. Given an interrupt (timeout), When `iris_execute` completes or times out, Then the
   cleanup attempt runs regardless.

### User Story 3 — Session state works with mac path (Priority: P2)

When `use_session: true` is set, the `%ctx` carrier must be available in the compiled
`.mac` routine the same way it is in the generated class method used by the HTTP path.

**Acceptance Scenarios**:

1. Given `use_session: true` and multi-line code that reads `%ctx.key`, When
   `iris_execute` routes via `.mac`, Then the session state is restored before execution
   and saved after.
2. Given session state set in a prior terminal-path call, When the next call is
   multi-line and routes via `.mac`, Then the prior session state is accessible in `%ctx`.

## Functional Requirements

- **FR-001**: Detection trigger — code routes to the `.mac` path when it contains at
  least one `{` character or at least one `\n` (newline). Single-line code with no `{`
  uses the existing terminal path unchanged.
- **FR-002**: Temp routine naming — the routine name is `IADTmp` followed by a
  hex-encoded UUID v4 (e.g., `IADTmpa3f1bc2d4e5f6789.mac`). Collision probability is
  negligible; no locking is needed.
- **FR-003**: Routine structure — the `.mac` file wraps the submitted code in a labeled
  entry point:
  ```
  IADTmpa3f1bc2d4e5f6789 ; auto-generated by iris_execute
   <submitted code lines, each indented with one space>
   Quit
  ```
- **FR-004**: Execution sequence:
  1. Write the `.mac` content to IRIS via `iris_doc(mode=put)`.
  2. Compile via Atelier REST (`iris_compile`).
  3. Execute via `iris_execute` terminal path: `Do ^IADTmpa3f1bc2d4e5f6789`.
  4. Delete the routine via `iris_doc(mode=delete)` — always, even on error.
  5. Return the captured output.
- **FR-005**: Response shape — the response includes a `transport` field:
  - `"terminal"` — single-line fast path (existing behavior, field may be omitted)
  - `"mac_compile_run"` — multiline path taken
- **FR-006**: Compilation errors are returned as-is in a `compile_errors` array matching
  the existing `iris_compile` error format. The routine is deleted before returning.
- **FR-007**: Session state (`use_session: true`) — when routing via `.mac`, the
  session restore and serialize steps that apply to the HTTP path apply equally. The
  `%ctx` object is available to the `.mac` code under the same name. The opaque session
  token in the response is updated to reflect state after `.mac` execution.
- **FR-008**: The `server` parameter is respected on the `.mac` path — all sub-operations
  (put, compile, execute, delete) target the same named server as the original call.
- **FR-009**: Gate enforcement — write gates (`mcpTemplate=live`, `mcpTemplate=test`) and
  the destructive gate (`Kill ^<global>`) apply before routing. A gated call is refused
  before any `.mac` is written.

## Key Entities

- **`iris_execute`** (tools/mod.rs, line ~4076): add detection logic before dispatch;
  add `mac_compile_run` sub-path.
- **`iris_doc` helper** (internal): reused for put and delete of the temp routine.
- **`iris_compile` helper** (internal): reused for the compile step.
- **Temp routine name generator**: small pure function in `iris_execute` — UUID + prefix.

---

## Success Criteria

- An agent submitting a 10-line `If/ElseIf/Else` block via `iris_execute` gets correct
  output with no manual intervention.
- The temp routine does not persist in the namespace after any outcome (success, compile
  error, runtime error, timeout).
- Single-line code performance is unaffected — no overhead on the fast path.
- Session state round-trips correctly across a terminal-path call followed by a
  `.mac`-path call.

---

## Out of Scope

- Rewriting block syntax to terminal-compatible form (the `.mac` path is the escape
  hatch; rewriting is error-prone and unnecessary).
- Supporting IRIS versions before Atelier API v1 (doc put/compile require Atelier).
- Caching or reusing compiled routines across calls (each call gets a fresh UUID).
- Changes to the WebSocket terminal session tools (`iris_terminal_open` etc.).

---

## Assumptions

- Atelier REST is available on the target server (NoPWS servers with `docker_only=true`
  are excluded from the `.mac` path; they fall back to `docker exec` as before or return
  a clear error if the code is multiline and docker-only).
- The agent's namespace has write permission for `.mac` documents and compile
  permission — same requirements as `iris_doc(mode=put)` today.
- UUID generation is available in the Rust runtime (via the `uuid` crate already in the
  workspace, or `rand` with a manual hex format).
