## Next Actions

### CRITICAL — Resolve Before `/speckit.implement`

**C1 — UnlockUser API reference in spec.md and tasks.md (Constitution II violation)**

This is the highest-priority fix. `spec.md FR-003` and `tasks.md T017` will direct an
implementor to write a call to `Security.Users.UnlockUser()` which does not exist on the
target platform. The correct API is already documented in `plan.md` and `contracts/` but the
normative spec and one task were not updated.

Files to update:

- `spec.md` line 13–14 (Overview): remove `##class(Security.Users).UnlockUser` reference
- `spec.md` line 128 (FR-003): replace `Do ##class(Security.Users).UnlockUser(username)` with `Security.Users.Modify` form
- `spec.md` line 211 (Assumptions): replace open "verify before implementation" caveat with confirmed result
- `tasks.md T017` description: replace `Do ##class(Security.Users).UnlockUser(username)` with `Security.Users.Modify`

**C2 — Missing Lift phase (Constitution IX violation)**

Constitution IX requires a dedicated lift phase before Polish with tasks to: (a) run the
benchmark A/B, (b) record results in `lift-results.md`, (c) gate merge on lift ≥ +0.20.
T033 exists but is in the Polish phase and covers only benchmark task creation, not
measurement. Options:

1. Add Phase 5.5 with explicit lift measurement tasks (required for new MCP tools exposed
   to agents).
2. If `iris_admin` qualifies for the IX exception (internal-only, not invoked by agents
   directly), document the exception in `spec.md` and `plan.md` explicitly — the current
   plan.md mentions "exception: internal-only orchestration actions" for Principle IX but
   the spec has no such exception claim, and the spec's own User Story framing describes
   an agent calling these actions directly.
